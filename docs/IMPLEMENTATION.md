## Design and optimization

Source-derived magenta/cyan identity, self-hosted Montserrat and Roboto, backup-sourced abstract colored-smoke video with a static poster fallback,
original logo recovered from the verified backup, no product photography, remote font requests, analytics pixels, or WordPress dependencies.
Static HTML and hashed assets; a small external client script handles Turnstile and form state.
Responsive grid, visible labels, keyboard focus, skip link, reduced-motion behavior, and a
persistent live status region. No numerical performance improvement is claimed without
repeatable comparative traces; this scope has no equivalent original support-page baseline.

## Form controls

- Same-origin JSON; maximum 16 KiB streamed body; field length checks and topic allowlist.
- Required consent, honeypot, independent peppered IP/email rate limiting (5/minute per edge location).
- Server-side Turnstile requires boolean success, action `support`, exact dev hostname.
- Finite provider timeouts; no client-visible provider errors or sensitive logs.
- Resend idempotency uses normalized content and a ten-minute bucket. It does not prevent
  duplicates across bucket boundaries; Turnstile separately rejects token replay.
- Primary delivery failure is a form failure. No automatic visitor email.
- Both escaped HTML and plain text, client branding, reply address, bounded Cloudflare context,
  and Wizards Services attribution. IP is excluded from email. Context is not used for recipient selection.
- Dev email is routed to the owner's review inbox. The page discloses this testing behavior.
